# 12. Testing strategy

The central testing problem for a tool like this: **the system under test depends on the live
internet, which is non-deterministic, and the correctness property we care about is "does not lie".**
The architecture is shaped to make that testable.

## The pivot: recorded evidence fixtures

`RawEvidence` is a serializable Pydantic model, and analyzers are pure functions over it. So:

```
backend/scripts/capture_evidence.py https://example.com --out tests/fixtures/evidence/example.json
```

captures one real collection run and commits it. From then on, every analyzer test is deterministic,
offline, fast, and reproducible on any machine. Network flakiness is confined to one opt-in test tier.

Fixtures are curated to cover the shapes that matter, not popular brands:

| Fixture | Represents |
|---------|-----------|
| `static_html_minimal` | plain HTML, no JS, no headers |
| `spa_client_rendered` | empty initial body + hydration payload + bundle |
| `ssr_hydrated` | content in initial HTML + hydration payload |
| `header_hardened` | full CSP/HSTS/COOP/CORP set, `SameSite` cookies |
| `header_bare` | no security headers, HTTP-only, cookies without flags |
| `mixed_content` | HTTPS document with active + passive `http://` subresources |
| `cookie_heavy` | many cookies with mixed attributes |
| `third_party_heavy` | many cross-origin scripts, no SRI |
| `collection_degraded` | browser stages missing (`dom`/`styles`/`perf` = `None`) |
| `empty_evidence` | only `target` present — the worst case every analyzer must survive |

Fixtures are stored as JSON, loaded through the model (so a schema change breaks loudly rather than
silently), and regenerated by an explicit command — never auto-updated by a test run.

## Test tiers

### Tier 1 — Analyzer unit tests (`backend/tests/unit/`, fast, offline)

For every analyzer, four mandatory cases beyond its happy path:

1. **Positive**: signal present → correct `status`, `value`, and non-empty `evidence`.
2. **Negative**: evidence present, signal absent → `not_detected` with a `reason`.
3. **Degraded**: required evidence slot is `None` → `unable_to_verify`, never an exception.
4. **Empty**: `empty_evidence` fixture → no exception, no invented values.

Plus cross-cutting property tests applied to *every* registered analyzer via parametrization:

- Determinism: `analyze(ev) == analyze(ev)` and no dependence on wall-clock or dict ordering.
- Provenance: every `verified`/`inferred` finding has ≥ 1 `EvidenceRef` (also enforced by the model
  validator, tested here at the analyzer level).
- Reasoned negatives: every negative finding has a non-empty `reason`.
- Namespacing: finding ids start with the analyzer id; ids are unique within the output.
- No I/O: analyzer modules are import-linted to forbid `httpx`, `socket`, `playwright`, `open`.
- No hostname special-casing: a grep-based test fails the build if a domain literal appears in
  `analyzers/` outside signature data files (guards axiom A10).

### Tier 2 — Scoring tests

Security scoring gets its own suite because it is the one place we assert a judgement:

- Each rule: pass / partial / fail / not-applicable / unknown paths.
- Weights sum to 100; per-category totals match doc 11 (a test parses this document's table and
  compares it to the code — the docs cannot drift from the rules).
- N/A exclusion arithmetic: a cookie-less site is not penalised.
- Band boundaries at 29.9/30/49.9/50/69.9/70/84.9/85.
- Band caps applied for HTTP-only and active mixed content.
- `minimum_applicable_points` gate returns `None` rather than a low score.
- Golden snapshot: `header_hardened` and `header_bare` fixtures produce exact expected scores.

### Tier 3 — Collection tests (`backend/tests/unit/collection/`)

- `target.py` guard: an explicit table of hosts — public, loopback (`127.0.0.1`, `::1`, `localhost`),
  private (`10/8`, `172.16/12`, `192.168/16`), link-local (`169.254/16` incl. `169.254.169.254`),
  CGNAT (`100.64/10`), reserved, multicast, credentials-in-URL, non-HTTP schemes, weird ports,
  decimal/hex/octal IP encodings, IPv4-mapped IPv6, trailing-dot hosts. Each with the expected
  verdict. DNS resolution is stubbed so the table runs offline.
- Redirect-hop re-validation: a public host redirecting to `127.0.0.1` must be blocked mid-chain.
- HTTP probe parsing with `respx`: header casing, multiple `Set-Cookie`, redirect chains, non-UTF-8
  bodies, oversized bodies (cap enforced), timeouts.
- Robots parsing: allow/deny/wildcards/empty file/404/HTML-instead-of-robots.
- Redaction: a URL with `?access_token=…` never appears unredacted in captured evidence.
- Probe JS files are syntax-checked and each has a contract test asserting the shape it returns
  (run against a local static page in the browser tier).

### Tier 4 — Pipeline and API tests (`backend/tests/api/`, offline)

The collector is behind a protocol, so tests inject a `FakeCollector` returning a fixture:

- Full pipeline over each fixture → valid `AnalysisResult`, correct section statuses.
- **Partial failure isolation** (the explicit requirement): a collector where `accessibility` is
  `None` and an analyzer that raises → scan status `completed_with_errors`, accessibility section
  `unavailable` with a reason, security section still `complete`, `errors[]` populated. This is the
  canonical regression test for axiom A7.
- Analyzer timeout → `AnalyzerRun.status == "timeout"`, rest of the report intact.
- Lifecycle: `POST` → 202, `GET` job state transitions, SSE emits `stage`/`progress`/`done` in order
  and terminates, `result` returns 409 while running / 200 when done / 410 after eviction,
  `DELETE` → 204 and subsequent `GET` → 404.
- Problem responses: each `ErrorCode` maps to its documented status and `problem+json` body.
- Admission control: concurrency limit returns 429 with `Retry-After`.
- Contract: `contracts/openapi.json` matches the live schema (fails if `make contracts` was not run).

### Tier 5 — Live scanner tests (opt-in, `backend/tests/live/`)

Skipped unless `WEBLENS_LIVE=1`. Never in the default suite, never gating a commit.

- Targets: `example.com` (minimal static), the local dev frontend build served on `127.0.0.1` via an
  explicit allow-loopback test override (a real SPA under our control), and one or two stable public
  sites for smoke coverage.
- Assertions are **structural, not value-based**: the scan completes, required stages ran, sections
  are populated, no analyzer crashed, evidence is non-empty. Never "example.com uses X" — that is
  outside our control and would make the suite a liability.
- A dedicated case asserts politeness: total requests to the target for one scan stays within the
  documented envelope (counted via the network ledger).

### Tier 6 — Frontend tests (`frontend/`, vitest + Testing Library)

| Area | Cases |
|------|-------|
| URL validation | valid/invalid/scheme-less/whitespace/IDN/local hosts, submit gating |
| Scan flow | mocked API: submit → running with stage list → persisted → dashboard; failure → problem banner; `completed_with_errors` → amber banner + affected section reasons |
| Persistence (IndexedDB) | `fake-indexeddb`: write/read round-trip with the full fixture result; survives a simulated reload (fresh DB open); delete removes rows from `scans`, `results`, **and** `screenshots`; migration + quarantine of a foreign `schema_version`; quota-exceeded fallback drops screenshots and sets `has_screenshot: false`; the same suite runs against `MemoryScanRepository` |
| Contract parsing | zod accepts the committed fixture result; rejects a result with a mutated `status` enum; `ContractError` surfaces as a message, not a crash |
| Report generation | each renderer against the fixture result: snapshot per file; unavailable section still produces a file containing its reason; evidence excerpts with `|` and backticks do not break tables; `analysis.json` is stable-ordered; zip contains the expected entry names; no `Set-Cookie` value appears in any output (a literal grep assertion) |
| Section components | render `verified`/`inferred`/`not_detected`/`unable_to_verify` findings with the right labels; `confidence` never appears in the DOM (asserted); interpretations render inside the interpretation callout only |
| Accessibility of WebLens itself | axe check on the main screen and dashboard; keyboard path from URL input to section nav |

The "confidence never appears" and "no cookie values in reports" tests are unusual but deliberate:
they encode product principles as executable checks, which is the only way principles survive
refactors.

## Tooling and gates

| Concern | Tool | Gate |
|---------|------|------|
| Backend lint/format | ruff | error on warnings |
| Backend types | mypy `--strict` on `domain/` and `analyzers/` | required |
| Backend layering | import-linter contracts | required |
| Backend tests | pytest (`-m "not live"`) | required |
| Frontend types | `tsc --noEmit` | required |
| Frontend lint | eslint | required |
| Frontend tests | vitest | required |
| Contract drift | `make contracts` + clean tree check | required |

Coverage is tracked but not a hard gate, with one exception: `analyzers/` and
`collection/target.py` must stay above 90% line coverage. Those are the modules where a silent gap
turns into a wrong claim about someone's website.

## Definition of done for any analyzer PR

1. Tier 1 four-case suite passes.
2. A fixture exists that exercises the new signal.
3. Limitations documented in `docs/limitations.md` and returned in `limitations[]`.
4. Report renderer handles the new finding shape (snapshot updated deliberately).
5. `make check` clean.
